# ADR-008: стек первого среза

Статус: принято как техническое допущение рабочего демо по заданию; фактическая риск-политика ждёт команды. Дата: 2026-11-09.

Предпосылка: [ADR-007](../sources/ADR-007.txt) принят для учебного проекта и остаётся без изменения статуса. Выбор PostgreSQL, primary-чтения, атомарность, история и outbox обязательны.

Решение: Kotlin/Compose Android; один Go-модуль с cmd/gateway, cmd/risk, cmd/network-collector. Gin для обоих HTTP API, OpenAPI 3.0.3 + oapi-codegen 2.4.1, gin-middleware, pgx/v5/pgxpool, sqlc 1.29.0, Goose. Детерминированные правила разделяют признаки и реакцию. Прямые простые функции и явные транзакции удобны для ревью участнику с опытом Java. Сравнивались Python/ML и ZEN из рекомендаций М-01: они требуют отдельной методики и не нужны для проверки транзакционного среза.

Локально один PostgreSQL 18 и синтетический источник. Симулятор услуги делит транзакционную БД, чтобы доказать порядок запрета и исполнения. Это ограничивает переносимость гарантии: отдельный владелец услуги требует нового протокола. Таблицы компактные, без production секций; нет автоматического удаления истории. Lifecycle и масштабирование по ADR-007 остаются обязательными перед приёмкой объёма.

Правила demo-v1 — исходный код policy + неизменяемая запись policy_version. Изменение/откат поведения требует новой версии и записи definition, а не редактирования старой. Каталог правил, shadow-прогон и переключатель активной политики ещё не реализованы (REQ-F27 частичен).

Справка по инструментам: [oapi Gin validator](https://github.com/oapi-codegen/gin-middleware), [sqlc configuration](https://docs.sqlc.dev/en/latest/reference/config.html), [Goose](https://github.com/pressly/goose). Версии проекта закреплены в go.mod и generate-командах; это не заявление о самых новых версиях.
