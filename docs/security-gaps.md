# Защитные пробелы

Сводка по `Antifraud_security_review.md` (SR-01–SR-10) и `security-review.md` (разделы 1–5), приложенным к задаче. Идентификаторы в таблице локальные. Статус относится к исходному серверному состоянию `59a6feb`. «Код» означает наблюдение в текущей реализации или конфигурации. «Открыто» означает, что последствия и размер эффекта требуют проверки. Исполняемые приложения к ревью в стенд не включены.

| ID | Пробел и основание | Критерий закрытия | Связь с ревью |
|---|---|---|---|
| SEC-01 | Профиль строится по двум последним регистрациям. Долговечность недавних рисковых фактов не гарантирована. Код — `RecentRegistrations`, `Ingest`. Точное окно открыто. | Согласовать срок действия и хранить значимый рисковый факт в этом окне. Проверить законные смены SIM и фактическое состояние услуги. | SR-01, §1 |
| SEC-02 | При `step_up` создаётся подтверждение. Старые разрешения той же операции требуют отдельной проверки на отзыв. Код — `evaluate`, `Deliver`. | После замены решения исполнение принимает только актуальное разрешение. Порядок фиксации покрыт защитным тестом. | §2 |
| SEC-03 | Подтверждение принимает тестовую строку. Модель восстановления открыта. Код — `Confirm`. | Подтверждение привязано к операции и ранее привязанному независимому аутентификатору. Восстановление защищено и проверено на устройстве. | SR-02 |
| SEC-04 | Внешние маршруты не проверяют субъект, внутренний API полагается на сеть, а состояние отдаёт историю. Код — `GatewayRouter`, `RiskRouter`, `State`. | Проверка принадлежности аккаунта, аутентификация сервиса и минимальный ответ клиенту. Отдельный авторизованный доступ к evidence для расследования. | SR-03, SR-04, SR-06 |
| SEC-05 | Разделение прав через `SET ROLE` опирается на учётную запись с расширенными правами в конфигурации стенда. Код — `Open`, `compose.yaml`. | Миграции и runtime используют разные учётные записи. Под runtime нет пути к расширению прав, изменению аудита или DDL. | SR-05, §4 |
| SEC-06 | `Drain` останавливает партию при первой ошибке. Предел влияния открыт. | Сбой одной доставки изолирован. Другие команды продвигаются, повторы ограничены, результат аудируется, история сохраняется. | SR-07 |
| SEC-07 | Контур демо использует HTTP и явно синтетические реквизиты, без контроля частоты запросов. Код — `compose.yaml`, `GatewayRouter`. | Для контура за пределами локального демо обязательны проверяемая идентификация, транспортная защита, управление секретами и лимиты. | SR-08–SR-10 |
| SEC-08 | Запросы `Decisions` и `Audits` выгружают всю историю аккаунта. Связь между её ростом, временем ответа и healthcheck открыта. | Состояние и healthcheck проверяются отдельно. Пагинация, лимиты и проверка на согласованном размере истории удерживают бюджет ответа. | §3 |
| SEC-09 | Повторная оценка и уникальность команды на операцию требуют согласованного жизненного цикла доставки. Код — `Ingest`, `Enqueue`. Последствия для повторного `allow` открыты. | Зафиксировать допустимость автоматического исполнения после переоценки. При принятой политике исход достижим, ограничен актуальной авторизацией и имеет ровно один эффект. | §5 |

Порядок для следующего среза — SEC-01 и SEC-02 с ментором, затем границы SEC-03–SEC-05. При изменении исполнения следуй ADR-007 и держи `account_guard` точкой упорядочения. Фиксированные E2E-проверки показывают заявленные защитные свойства для выбранных случаев. Для закрытия ID нужны результат по его критерию, коммит, версия стенда и ссылка на прохождение в [отчёте](verification.md).
